# RoadStar design direction

Audience: carrier dispatcher on a large screen; driver operating a phone while parked. Serve Industry Impact (25%), Technical Execution (20%) and Presentation (15%); published weights remain incomplete. Scope remains the full fleet platform. Product claim: clear integrated execution and traceable recovery approval.

Grounding: Carbon data tables (https://carbondesignsystem.com/components/data-table/usage/) contribute dense, selectable operational rows and explicit empty/loading states. Samsara telematics (https://www.samsara.com/products/telematics) contributes a persistent map next to fleet context. Radix Alert Dialog (https://www.radix-ui.com/primitives/docs/components/alert-dialog) contributes keyboard/focus-safe consequential confirmations. Structural references only; no copied branding/assets.

Grounding system: owned React components on Radix primitives; TanStack Query/Table. Mobile uses native React Native controls, identical semantic labels and colors, larger touch targets.

ONE signature: the recovery comparison strip. Current assignment and proposed replacement share a horizontal time axis; the dock delay and affected next load are directly visible. All other surfaces are quiet operational panels. Show assumptions and a separate explicit approval action. No decorative animation.

Dark dashboard tokens: background oklch(0.22 0.033 248), foreground oklch(0.95 0.012 245), card/popover oklch(0.27 0.034 248), primary oklch(0.74 0.10 245), primary foreground oklch(0.20 0.04 248), muted oklch(0.32 0.03 248), muted foreground oklch(0.78 0.025 245), border oklch(0.40 0.03 248); accent and destructive preserve accessible foreground pairing. This is blue/amber, not a near-black neon dashboard.
Type: IBM Plex Sans body; IBM Plex Sans Condensed headings. Bundle font assets through Fontsource on web. 12/14/16/20/28/36px scale, tabular numerals. Mobile native fallbacks must remain legible if custom font isn't loaded.
Space: 4px base; 8px controls, 16px cards, 24px panels; radius 8px; motion <=120ms focus/hover only. Touch targets >=44px. Text status labels never color alone.
Layout: web 208px nav + fluid workspace; top operational status, 2:1 map/planning and inspector; details use accessible dialog or side panel. 900px collapse nav and stack workspace. Mobile: Today / Trips / Duty / More tabs; current trip and next action first, manifest and documents in same context. Dispatcher mobile has exceptions and approvals; no desktop table shrunk to fit.
Inventory: fleet table, load cards, manifest, map panel, recovery comparison, evidence drawer, approval dialog, synchronization banner, tracking-session control, document queue.
Content: synthetic records labeled; historical source rows never become live telemetry. Show missing route/map/configuration as actionable unavailable state. No mocked API success, fabricated route geometry, fake optimization metrics, or disguised native verification.
Critique (one pass): color and type are restrained; signature is concentrated in the time/assignment comparison. Approval and driver delivery/acceptance remain separate. Stronger than a generic KPI dashboard because the affected load and recovery decision are the focal action. UI implementation must not claim road feasibility before routing is integrated.
